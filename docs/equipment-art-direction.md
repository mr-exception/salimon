# Scout equipment and modular ship artwork
Approved phase 3, 2026-11-26. Existing [Scout interior](scout-interior-art-direction.md), [construction](scout-and-modular-construction.md), [survival](spacesuit-and-hazards.md) and domain footprints govern actual gameplay. One starting spaceship named Scout; player expands/customizes the same vessel. No purchasable/craftable complete ship packages or classes in current scope. Progression is construction and equipment, not replacement.

## Modular ship
Utilitarian ivory/graphite hull, ochre access points, recognizable propulsion and supports, restrained light, localized wear. Starting layout stays authoritative. Reusable straight/corner/end hull, walls (solid/partition/window), floor sections, doors, windows, thrusters, lights and independent machines; neighbor-aware joins without seams, shared connections and material masks. No forced symmetry; future exterior silhouette derived from constructed state. Rooms defined visually by installed equipment/furnishing/materials, not mandatory room packages. Cockpit cool graphite/instruments; habitation warm ivory/fabric; engineering steel; cargo reinforced floor; entry protective markings. Cozy maintained home with bunk, galley, personal storage, privacy screen, observation window/shutter, seating and personal objects; decorative fixtures do not falsely imply interactions. Permanent accessible cutaway, future full exterior representation from same state, no new inspection mode. Prepare compatible modular artwork, do not implement construction/relocation/grid/structural/power network/cosmetic interfaces now.
Machines authored standard forward, support four cardinal rotations with anchors, access/input/output and connection references rotated consistently; text separate, environment shadows independent. Integrated recessed utility rails/floor/wall infrastructure, no fake functional cables; future engineering overlay only if network exists. New components clean, cosmetic wear preserved where supported, repairs restore affected component. Material masks for hull paint, floor/wall/furniture finishes and decorative light; semantic warnings immune to customization.

## Machinery
Core rounded/cylindrical reinforced reactor with subtle cyan activity and energy indicator; Fabricator rectangular enclosed processing chamber, intake/output tray; Gear Crafting Bench open work surface, tools/mounts distinct from Fabricator; raw Resource Container reinforced lid/capacity; equipment cabinet organized suit/module compartments; cockpit physical desk/chair and sensor controls. Recognizable functional front and clear access; metadata references authoritative footprint/anchor. Physical integrated state indicators (not floating progress bars); exact values in interface. Idle dim, active motion/light, unpowered dark/stopped, paused stationary with status, output ready persistent small cue, blocked amber, fault red only if actual fault, damage overlays only if supported. No invented failures. Door/containers/cabinet access, machinery work, fan where appropriate, furniture supported interactions; state-driven motion/sound. Normal warm light, localized cyan; unpowered readable minimum; emergency light only with approved source/mechanic. No total blackout navigation obstruction. Takeoff/landing: actual engine state, clearance/shadows, material/atmosphere-dependent disturbance, touchdown, supports; no fake vacuum weather or altered physics/duration.
 
## Equipment
Tierless suit always equipped indoors/outdoors; no automatic clothing/helmet swap. Modular layers, recognizable temperature insulation/heat exchange, radiation shield housing, toxicity filters/cartridges, future backpack storage; tier refinement within same functional shape/anchors, no RPG rarity rainbow or oversized superhero gear. Held tools only when equipped; practical handles and working parts, extraction not weapon silhouette. Three-quarter inventory icons per production guide; same object identity as world sprite. Durability overlays: >=80% maintained, >=40% and <80% minor wear, >0% and <40% deterioration, zero broken/destroyed per domain; broken suit remains until replaced/repaired, destroyed modules disappear per state, cosmetic aging independent, repairs restore appearance. Thresholds presentation only; no damage sources introduced.
Initial slice: hull/interior → character/suit → Core/Fabricator/bench/storage/cabinet/cockpit/door → tools/modules/icons → habitation → lighting/motion → integrated acceptance. Reuse existing gameplay; no new ship classes.

### Scout modular cutaway

The playable SVG Scout assembles its bow, side rails, aft corners, propulsion
housings, three deck zones, wall caps, glazing and boarding-door panels in the
existing ship-local view. Wall ends join where the published footprint meets a
neighbor at the seam. Cabin, cockpit and cargo finishes share the existing
positions. Door leaves follow the saved closed state and leave the open
threshold visible. Wall caps and furniture near the player’s foreground
silhouette can fade to 26% opacity over 190 ms. Reduced-motion preference makes
that change immediate. The cues and the door state remain visible. All
collision, movement, interaction anchors and save data remain domain-owned.

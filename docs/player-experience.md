# Complete browser player experience
Approved phase 6, 2026-11-26. Future presentation targets; preserve [narrative](narrative-and-lost-journey.md), [Archive](archive-recovery-and-navigation.md), [endgame](absenat-and-hall.md), [HUD](hud-ui-style-guide.md) and actual gameplay/save contracts.
 
Minimal cinematic main menu with celestial background/static reduced-motion option; Continue, New journey, Settings, Credits; no spoilers, promotions or forced accounts. Playable awakening with short fade, unfamiliar environment, equipment, Scout shelter, physical investigation and fragmented records; actual approved start conditions govern. Optional short contextual first-use guidance for movement/right click, gathering, weight/storage, Core, crafting, hazards, cockpit, takeoff; dismiss without immediate repeat, completion tracked on actual action, preserve preferences, new mechanic guidance, searchable/reopenable help by category. No mandatory tutorial campaign.
Self-directed immediate needs, personal objectives and narrative leads; no compulsory quests, XP gates, daily missions or permanent quest arrows. Progress through equipment, knowledge and continuous expansion of same Scout; no packaged ship classes. Prepare future character/ship naming, suit cosmetics and personal decorations, not initial character creation/customization UI.
Narrative through physical places, records, signals, Archive and rare sites; distinguish confirmed, incomplete, unverified and corrupted; no forced explanations. Searchable structured Archive (recovered facts) separate from expedition journal (player observations/visits); respect scanner knowledge. Discovery confirmation scaled to significance, optional notes, restrained music for major discoveries, no confetti or artificial rewards. During travel support existing onboard actions, truthful location, velocity, destination, estimated duration if calculable, energy and warnings; no new autopilot/time acceleration. Jump Drive quantum staging follows approved separate contract.
Initial loading truthful progress/error/retry, no artificial delay; seamless ordinary movement/door/flight, short sensor transition. Pause menu Resume, Settings, Controls/help, Return to main; preserve current pause semantics, future multiplayer separate. Settings independent of journey: graphics, audio, controls, accessibility, general/tutorial/language. Persistent preferences, accessible scale, key/mouse settings subject to existing controls. Autosaves use existing persistence, temporary verified saving indicator, truthful failure and recovery, Continue, confirmation before destruction; no new slots/cloud checkpoints. Refresh restores valid save, single-writer tabs, compatible update, GPU recovery, missing asset fallback/essential error, unsupported browser explanation, corrupted save safe options; never silently reset/overwrite. 
Death restrained Journey ended with actual cause and available location/duration/visited/distance stats, no invented metrics, explicit new journey and existing terminal/reset rules; no resurrection/rollback. Absenat/Hall distinctive ending with actual record, closure and music; no spoilers, mechanics separate.
UI consistent empty/loading/unavailable/error states with explanation/action, no raw exceptions. Desktop-first CSS viewport targets 1280x720 minimum, 1366x768, 1920x1080 reference, 2560x1440, 3440x1440, 3840x2160; no stretch, bounded HUD scale, usable panels, mobile deferred. Readable sans-serif, tabular numerals, existing adaptive SI formats authoritative; locale-ready strings separate from art/domain, variable length, number formatting, future direction/fonts; English initially, translations separate.
Branding: minimal wordmark with orbital symbol, mono variant, favicon, app icon, social preview, typography/spacing, owner-approved reference package, no spoilers. Website shares identity but prioritizes usability, actual gameplay screenshots vs clearly labeled concept, description/version/credits; no misleading marketing. Avoid engagement pressure, FOMO, login rewards, artificial timers, excessive notifications, intrusive promotion; business model separate.
Acceptance: built actual-control start → guidance → gather/store → Core/manufacture → protection → exposure → safe return → cockpit → takeoff/travel/land → second environment → save/reload → accessibility/death; future narrative/endgame only when underlying contracts delivered. Actual screenshot/audio/functional evidence, not unit tests alone.

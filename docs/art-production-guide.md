# Browser art production foundation
Owner-approved 2026-11-26 (phase 2). Future delivery, not implementation evidence. See [master direction](browser-art-direction.md) and [acceptance](acceptance-policy.md).

## Authoring and assets
Hybrid AI-assisted individual illustrations and reusable modular layers for characters, suits, machines, furniture, tools, resource families and icons; seamless textures and procedural deterministic terrain composition; programmatic light, particles and effects; React/SVG UI and Three.js celestial rendering. Never require AI generation for build, CI, Coolify deployment or runtime. Registered placeholders allow development when generation unavailable. Pipeline: specification (purpose, dimensions, orientation, anchors, states) → reference and prompt → generation → crop/alpha/align/color-correct → optimize and package → automated validation → integrate authoritative state → actual browser visual review. Preserve source, prompts, reference provenance and licensing where available. Shared prompt: strict 90° overhead world illustration, stylized semi-realistic grounded industrial sci-fi, believable proportions, neutral overhead material shading, controlled texture, no thick outlines, directional cast shadows, text/watermark. Asset-specific prompt names dimensions, palette, function, orientation, anchors, states and layers. Inventory icons are an explicit perspective exception.
 
Initial source density 128 px/m (benchmark against current 64 texels/m and 32 terrain); transparent padding excluded from physical dimensions. Large structures assembled from sections; overhead footprint not standing height. PNG/editable originals; WebP alpha world/item sprites (lossless for critical edges, high-quality lossy if acceptable), WebP terrain, SVG UI, WebP animation atlases, JSON metadata. Inventory icons 256x256 source, transparent, centered/padded, three-quarter view, neutral light, no baked labels/counts. Natural variations targets: rocks 4–8, deposits 3–5, biological families 4–8, textures 3–6, furniture 1–3 per model, wear 3–5, machinery one per model. Seeded rotation/scale/tint only if compatible with physical footprint. Character layers synchronized: body, suit/helmet, modules, backpack when equipped, held tool, condition and separate shadow; continuous facing, common hand/helmet/module anchors, no combination explosion. Hybrid limb motion, sprite sequences and procedural motion; initial 8–12 walking poses, complex sequences 12–24 fps, independent of display/simulation clock. State-driven doors, machinery, mining, lights and particles.

## Packaging
Adapt existing repo layout: client/assets category groups and client/src/rendering adapters; art/sources, references, prompts, validation for authoring; runtime assets separate. Stable versioned IDs, category, texture references, physical width/depth, normalized pivot, source density, layers, state/animation/attachment references, optional occlusion/audio references, production status. Metadata references domain footprints/anchors, never duplicates gameplay recipes/collision/power. Saves reference gameplay IDs, never file names or atlas coordinates. Artwork revisions do not migrate saves; physical/identity changes require separate domain approval and migration.
Deterministic automatic atlas packing with padding/extrusion, generated coordinates, default max 2048²; groups by usage; no hand-maintained atlas coordinates. Content-hashed URLs, initial essential assets only, lazy regional/navigation loads, preload known destinations, release under memory pressure; missing decorative assets use explicit placeholder; essential failures recoverable. Optimized runtime assets, SVG, metadata, prompts and small references in Git; large editable sources use approved external storage/LFS only when justified; rejected attempts ignored; ordinary builds reproducible without proprietary tools.
Lifecycle placeholder → draft → approved → production → deprecated; placeholders tracked and replaceable without gameplay changes. Record origin, rights, attribution, redistribution, reference provenance; no unknown-license packs or copies of commercial game art. Owner approves foundational references/new styles/redesigns, agents can produce matching family variations; technical review separate from art signoff.

## Validation
Reference scenes: Scout interior/exterior, character/equipment, mining, machinery, hazards, panoramic navigation, inventory/equipment UI. Fixed seed, camera, viewport/DPR, clock and lighting; original captures and comparison under existing acceptance policy; no automatic replacement of approved references. Keep runtime evidence in existing ignored test-results/CI artifacts and PR record, not committed evidence-only directories. Owner review for art direction/reference approval is not an added CI gate. Cloud validation first; physical/hardware/subjective qualification separate.
